Encryption of clinical records at rest is usually specified as ``AES-256'' and judged by throughput, a specification that says nothing about whose record a ciphertext belongs to. An insider with write access to the database can move an encrypted field from one patient's row to another's, and the application, decrypting for the row it believes it is reading, presents the wrong patient's data with no error. We show this record-swap attack succeeds against shared-key AES-CBC with HMAC and against per-tenant AES-GCM without associated data, both common deployments, and that per-tenant AES-GCM with the record's context bound as associated data stops it. The question for clinical records is therefore not whether to bind but what to bind, how to encode it, and under which key. We present CPDPM, which answers it: the context of tenant, patient, resource type and field path is encoded injectively, used to derive a per-context key from a versioned master key through HKDF, and bound again as associated data to a standard AEAD, with a key commitment against partitioning oracles, versioned rotation, and a single failure mode. Measured against the associated-data baseline, CPDPM matches it on every substitution, and the per-context key reduces what one leaked key exposes from every record of a tenant to one field of one patient, so that containing the leak means re-encrypting one record rather than a tenant, while versioning makes retirement of a key a cryptographic fact. For FHIR resources an encrypted manifest binds the set of encrypted fields, detecting deletion, reordering and per-field replay, and a streaming mode extends the guarantees to large payloads. Security reduces to standard AEAD notions (proof sketch). We also examine the keyed byte-level pre-transform layers placed in front of AES in hybrid health-record schemes: such a layer adds no diffusion, contributes nothing when its key travels with the ciphertext, and for the most common instance, the per-byte affine map, has exactly $2^{\KeyspaceLog}$ instances, shown by exhaustive check. The fixed cost is about \CpdpmFixedUs{} microseconds per operation over raw AES-GCM. Implementation, tests and experiments are released.
